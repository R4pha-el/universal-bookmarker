> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the native iPhone saving library, Share extension, and private shared-backend contract using the user's folder-card and dark-login references.

**Architecture:** A portable BookmarkCore Swift package owns domain types, validation, search and durable capture manifests. The main SwiftUI app owns SwiftData and original files; a serial sync service uses authenticated Supabase RPC/storage endpoints. The extension writes scoped App Group manifests, never the main database.

**Tech Stack:** Swift 6, SwiftUI, SwiftData, Foundation, PhotosUI, Quick Look, Supabase Postgres/Storage/Auth, Deno account-deletion function, Xcode project, macOS CI.

**Spec:** `docs/superpowers/specs/2026-10-23-universal-bookmarker-ios-design.md`

## Review Focus

1. Account switching during extension capture must never reassign a queued manifest.
2. A failed persistence write or interrupted original copy must never report a successful save.
3. Sync retries must not duplicate records or overwrite immutable objects.
4. Deleted collections must not delete their items; deleted items must not return from an offline device.
5. Unconfigured cloud access must show device-only status and never claim sync completion.

## Shared interfaces

`BookmarkCore` defines public Codable/Sendable values: `BookmarkKind` (link/photo/pdf/file), `BookmarkItem`, `BookmarkCollection`, `LibraryScope`, `SyncStatus`, `CaptureManifest`, `CaptureAttachment`, and `DestinationDescriptor`. UUIDs are stable; original files are referenced by relative names. `BookmarkItem` fields: `id`, `title`, `kind`, `url: URL?`, `filename: String?`, `localFileName: String?`, `contentType: String?`, `byteCount: Int?`, `note`, `collectionID: UUID?`, `createdAt`, `updatedAt`, `deletedAt: Date?`, `version: Int64`, `scopeID: String`, `syncStatus`. Collections have `id`, `name`, `tint`, `createdAt`, `updatedAt`, `deletedAt`, `version`, `scopeID`.

`LibraryStore` is a main-actor observable class in the app. UI consumes `items`, `collections`, `scopeID`, `syncMessage`, `errorMessage`, `isBusy`; it calls `addLink`, `importFiles`, `updateItem`, `deleteItem`, `createCollection`, `renameCollection`, `deleteCollection`, `moveItem`, `loadDemoLibrary`, `retrySync`. Root implementation owns persistence and sync adapters; UI ownership is limited to Views/ and Design/.
